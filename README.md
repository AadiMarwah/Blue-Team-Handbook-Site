# 🛡️ Blue Team Handbook

Notes and research from my journey learning **defensive cybersecurity and Security Operations Center (SOC) operations**.

This repository is where I organize and document what I learn while exploring different areas of Blue Team security. While studying these topics, I quickly realized how much information is scattered across courses, documentation, labs, blogs, and tools. Keeping everything separate made it difficult to connect the dots, so I started bringing my notes together in one place where I could **track what I’m learning and revisit it whenever needed**.

Over time, this grew into a structured collection of notes covering different parts of the defensive security landscape. It’s not meant to be formal documentation — think of it more as a **growing knowledge base from someone actively learning and exploring the field**.

---

## 🧠 What you'll find here

The notes here explore several areas that frequently appear in **SOC environments and security investigations**.

A large portion focuses on **SOC technologies** — including SIEM platforms, EDR solutions, SOAR tools, and stacks like ELK and Splunk. These are the systems analysts rely on to transform massive amounts of log data into meaningful alerts and investigations.

Another major area is **Digital Forensics and Incident Response (DFIR)**. Here I explore tools like Volatility for memory analysis, using KAPE for artifact collection, investigating Windows Registry artifacts, and examining forensic workflows across both Windows and Linux systems.

There’s also a strong focus on **network visibility and monitoring** — understanding traffic with Wireshark, intrusion detection with Snort, and learning what normal network behavior looks like so unusual activity becomes easier to identify.

Beyond the tools themselves, I’m also trying to understand the **broader defensive strategy** — studying malware behavior, exploring frameworks like the Pyramid of Pain,Cyber Kill Chain, and learning how defenders approach detection and response.

Finally, there are notes on **how SOC teams actually operate**, including alert triage, reporting workflows, metrics, and the internal processes that help analysts manage investigations effectively.

---

## 📚 Why I keep this project

A lot of cybersecurity learning happens through **experimentation, repetition, and hands-on practice**. Writing things down in my own words helps reinforce what I learn and creates a reference that I can return to later.

This repository is simply my attempt to keep that learning process **organized, practical, and continuously improving**.

If you’re also learning about **SOC operations, DFIR, or defensive security**, some of these notes might be helpful as you explore the field.

## 🔄 Work in progress

This project grows as I continue learning.

New notes are added regularly, and existing ones are updated whenever I revisit a topic or come across something new. In many cases, updates happen **daily while I’m actively studying or working through labs**.

Since defensive security is constantly evolving, this repository evolves with it.
